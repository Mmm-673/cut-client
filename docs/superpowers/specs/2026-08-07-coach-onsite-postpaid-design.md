# 助教现场开单与后付费（会员端）设计文档

> 日期：2026-08-07
> 状态：待评审
> 范围：用户 App（会员端）

---

## 1. 背景与目标

### 1.1 背景

现有"初球"App 只有"用户预约、服务前付款"的预约订单流程。本次新增独立的"助教现场开单、服务结束后付款"流程，订单由助教创建，会员端只能查看和支付。

### 1.2 目标

- 会员可在 App 中查看自己的现场订单（进行中 / 待付款 / 待评价 / 已完成）
- 服务结束后，会员可在 App 内完成微信 / 支付宝支付
- 支付成功后可进入评价流程
- 完全独立于现有预约订单流程，不影响现有功能

### 1.3 版本兼容

- 请求头 `client-version > 1.0.0` 才开放现场订单接口
- 现有 `request.js` 已携带 `client-version: 1.0.1`，满足条件，无需额外处理
- 收到错误码 `1010000337` 时提示升级并停止重试

---

## 2. 整体架构

### 2.1 架构原则

- **完全独立**：现场订单是独立流程，不复用预约订单页面
- **零侵入**：不修改现有订单页、订单 API、支付核心函数
- **复用底层能力**：支付工具的渠道执行逻辑、请求封装、评价页等底层能力可复用

### 2.2 用户流程

```
"我的"页面
  → 现场订单入口
  → 现场订单列表页
    → 现场订单详情页
      ├─ 进行中（只读 + 实时计时）
      ├─ 待付款 → 支付弹窗 → 支付 → 轮询结算 → 待评价
      ├─ 待评价 → 跳转评价页
      └─ 已完成（只读查看）
```

### 2.3 状态流转（会员视角）

```
40 进行中（服务开始后会员端才可见）
  → 45 现场待付款
    → 50 待评价（支付结算成功后）
      → 60 已完成（评价后）
```

## 4. API 层设计

### 4.1 `api/billiard/onsiteOrder.js`

| 函数 | 方法 | 路径 | 说明 |
|------|------|------|------|
| `getOnsiteOrderPage(params)` | GET | `/app-api/billiard/onsite-order/page` | 会员现场订单分页列表 |
| `getOnsiteOrderDetail(id)` | GET | `/app-api/billiard/onsite-order/get` | 会员现场订单详情 |

分页参数：`pageNo`（默认1）、`pageSize`（默认10，范围1～200）

### 4.2 `api/billiard/onsitePay.js`

| 函数 | 方法 | 路径 | 说明 |
|------|------|------|------|
| `createOnsitePayment(data)` | POST | `/app-api/billiard/onsite-payment/create` | 创建现场支付尝试 |
| `getOnsitePaymentStatus(orderId)` | GET | `/app-api/billiard/onsite-payment/status` | 查询支付和结算状态 |

`createOnsitePayment` 请求参数：
- `orderId`：现场订单 ID
- `channelCode`：渠道编码，`wx_app` 或 `alipay_app`

### 4.3 金额单位

所有金额均为整数分，前端展示时除以 100 转元，使用 `.toFixed(2)` 格式化。

- 入口："我的"页面 → 现场订单

```
导航栏：现场订单 + 返回
├── [下拉刷新]
```

### 5.3 订单卡片展示规则

| 状态 | 状态标签颜色 | 主要信息 |
|------|-------------|----------|
| 40 进行中 | 蓝色 | 开始时间、小时单价、返程车费 |
| 45 待付款 | 橙色 | 服务时长、应付金额 |
| 50 待评价 | 绿色 | 服务时长、实付金额 |
| 60 已完成 | 灰色 | 服务时长、实付金额 |

### 5.4 服务类型映射

```js
const serviceTypeMap = {
  1: '台球指导',
  2: '潮玩领航',
  3: '酒艺品鉴',
  4: '影视赏析'
```

### 5.5 核心逻辑

1. **分页加载**：`pageNo` + `pageSize=10`，下拉刷新 + 上拉加载更多，用 `id` 去重
2. **点击卡片**：`uni.navigateTo({ url: '/subpkg/onsite/detail?id=' + order.id })`
3. **`onShow` 刷新**：每次页面显示时刷新第一页（支付后状态可能变化）
4. **入口守卫**：`onLoad` 调用 `guardReviewEntry()`

## 6. 现场订单详情页

### 6.1 页面信息

- 路径：`subpkg/onsite/detail.vue`（分包）
- 导航栏标题：订单详情
- URL 参数：`id`（订单 ID）

### 6.2 按状态渲染

#### 状态 40：进行中

- 顶部状态卡片：🔵 服务进行中 + 实时计时（HH:MM:SS）
- 服务信息卡片：服务类型、开始时间、小时单价、返程车费
- 助教信息卡片：头像、姓名
- 订单编号
- **底部无操作按钮（只读）**

#### 状态 45：待付款（paymentStatus = 0）

- 顶部状态卡片：🟠 待支付 + 应付金额
- 服务信息卡片：服务类型、开始/结束时间、实际时长、计费分钟、小时单价、返程车费、应付金额（醒目）
- 助教信息卡片
- 订单编号
- 底部操作栏：**去支付**按钮

#### 状态 45 + paymentStatus = 10（已支付，结算中）

- 顶部状态：支付成功，订单处理中...
- **隐藏所有支付按钮**
- 显示处理中提示

#### 状态 50：待评价

- 展示完整订单信息 + 实付金额
- 底部操作栏：**去评价**按钮
- 点击跳转：`/subpkg/coach/evaluate?orderId=xxx&coachId=xxx`

#### 状态 60：已完成

- 展示完整订单信息 + 实付金额
- 底部无操作按钮（纯展示）

### 6.3 实时计时（状态 40）

- 本地计时：基于 `startTime` 和 `Date.now()` 计算，`setInterval` 每秒更新显示
- 后端校准：每 30 秒轮询一次详情接口，校准时间并检测状态变化
- 检测到状态变为 45 时：停止计时轮询，刷新为待付款状态
- 计时格式：`HH:MM:SS`

### 6.4 支付弹窗

- 弹窗样式复用现有支付弹窗
- 只显示**微信支付**和**支付宝支付**两个渠道
- 不显示钱包支付
- 显示支付金额（锁价金额）
- 确认支付按钮 + 防重复点击 loading

### 6.5 支付后轮询

支付成功后启动支付状态轮询：

- 调用 `getOnsitePaymentStatus(orderId)`
- 间隔：2.5 秒
- 上限：30 次（约 75 秒）
- `paymentStatus = 10` → 关闭支付弹窗，隐藏支付按钮，显示处理中
- `settlementStatus = 20` → 停止轮询，刷新订单详情（进入待评价）
- `settlementStatus = 30` → 降低频率继续查 5 次，仍不成功则提示"支付结果确认中"
- 超时：提示"支付结果确认中，请稍后刷新查看"，用户可手动刷新

### 6.6 前后台切换

- `onHide`：暂停所有轮询（计时校准 + 支付状态）
- `onShow`：立即查询一次 + 恢复轮询

### 6.7 入口守卫

`onLoad` 调用 `guardReviewEntry()`，审核模式下直接返回。

## 7. 支付流程设计

### 7.1 核心原则

- 不修改 `utils/payment.js` 中任何现有函数
- 复用 `executePayment` 的支付渠道执行逻辑
- 现场支付逻辑独立封装为新函数

### 7.2 `executeOnsitePayment(options)`

新增函数，放在 `utils/payment.js` 末尾。

**参数：**
- `orderId`：现场订单 ID
- `channelCode`：支付渠道编码
- `onPaymentSuccess(paymentInfo)`：原生支付成功回调（通知页面隐藏支付按钮）
- `onSettlementSuccess(orderDetail)`：结算成功回调（刷新订单详情）
- `onError(error)`：错误回调
- `onCancel()`：取消回调

**流程：**

```
1. 调用 createOnsitePayment({ orderId, channelCode })
   → 获取 payOrderId
   → 失败：onError 回调

2. 调用 executePayment({
     payOrderId: payOrderId,
     channelCode: channelCode,
     onSuccess: ...,
     onError: ...,
     onCancel: ...
   })
   → 拉起原生支付
   → 取消：onCancel 回调
   → 失败：onError 回调

3. 原生支付成功
   → onPaymentSuccess 回调（通知页面隐藏支付按钮）
   → 启动支付状态轮询

4. 轮询 getOnsitePaymentStatus(orderId)
   → settlementStatus = 20 → onSettlementSuccess 回调
   → 轮询超时 → onError 回调（pending 状态）
```

### 7.3 轮询器实现

独立的 `createPoller` 工具函数（放在 `utils/payment.js` 中，仅供现场支付使用）：

- 支持 `start()` / `stop()` / `pause()` / `resume()`
- 可配置间隔、最大次数
- 支持暂停/恢复（用于前后台切换）

## 8. 错误处理

### 8.1 错误码映射

在 `utils/error-messages.js` 中新增：

| 错误码 | 消息 | 客户端处理 |
|--------|------|-----------|
| 1010000337 | 请升级客户端后使用现场开单 | 停止重试，提示升级 |
| 1010000338 | 当前现场订单状态不允许该操作 | 刷新订单详情和按钮状态 |
| 1010000341 | 现场订单尚未结束或金额未锁定 | 刷新订单，等待结束锁价 |
| 1010000342 | 现场订单已支付 | 关闭支付入口，查询状态 |
| 1010000343 | 收银台凭证无效或已过期 | 忽略（会员端不涉及） |

### 8.2 处理原则

- 通用错误（网络错误、参数错误）由请求拦截器统一处理
- 业务错误码在页面级或支付回调中针对性处理
- 页面级错误处理优先刷新订单状态，再给用户提示
